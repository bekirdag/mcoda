# Retrieval and code intelligence

Prefer local repository evidence first: docdex_search, then docdex_open for precise slices. Use returned paths/doc IDs and line provenance; do not infer unseen source. Use docdex_tree for structure, symbols/ast for definitions, impact_graph before source changes and impact_diagnostics for unresolved/dynamic imports. Empty graphs are incomplete evidence: inspect callers before claiming safety. Export the search result's dag_session_id with dag_export to inspect the reasoning trace and order dependent changes.

For recent changes use search diff controls (working tree, staged, reference range and paths) when exposed by the active schema. For weak results check repo_inspect, stats and files; index selected missing/stale files rather than blindly rebuilding everything. The host handles repository initialization and isolation. Never rebind to another repository to resolve missing_repo/unknown_repo.

Read capabilities before optional batch_search or rerank. Batch related queries within returned limits; rerank actual retrieved candidates, not invented hits. Respect truncation, returned_count, effective query counts and token bounds. Use indexed library docs with include_libs where advertised. The host-side docdexd libs discover/fetch commands ingest dependency docs; they are CLI operations, not fabricated MCP tool names. If no authorized host execution is available, use available research tools and disclose that library ingestion could not run.

For external/current facts use docdex_web_research with force_web where exposed. Skip local search for explicitly external questions when supported. Bound web_limit/no_cache and respect rate-limit backoff. Docdex owns provider selection (mswarm, DuckDuckGo, SearXNG and configured API fallbacks); do not bypass it by reading API keys or constructing raw provider requests. Inspect primary source pages with browser tools when needed. Cite actual supporting content and distinguish snippets/discovery links from fetched documents. Resolve relative dates with server_time.

Raw MCP and HTTP schemas differ from some Codali convenience tools: e.g. open may use startLine/endLine, while raw MCP uses start_line/end_line. Discover actual schemas. HTTP service binding uses /v1/initialize with rootUri, health is /healthz, search is /search and snippets /snippet/:doc_id. Codali manages these internally; don't run curl to bypass tool permissions. Context-injecting chat is a host integration, not a substitute for evidence or a second uncontrolled model loop.

Recover boundedly: invalid_range → adjust/clamp using actual file bounds; stale_index → permitted targeted index; missing_repo/unknown_repo → report binding failure to host; rate_limited → back off; connection failure → use permitted local files/search and explain missing structural analysis. Never repeatedly retry unchanged calls or claim unobserved results.
